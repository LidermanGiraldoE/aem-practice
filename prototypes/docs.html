Modelos de componentes

Define qué campos ve el autor en Universal Editor y cómo se convierten en el markup que recibe tu bloque.

Universal Editor Actualizado el 20 oct 2026 · 6 min de lectura

Introducción

Cada bloque que aparece en Universal Editor necesita tres piezas: una definición (cómo se llama y qué plantilla crea), un modelo (qué campos tiene) y, si es un contenedor, un filtro (qué hijos acepta).

i
Archivos generadosNo edites component-models.json a mano. Edita los parciales y ejecuta npm run build:json.

Estructura de archivos

Cada bloque guarda su configuración junto a su código, en un parcial que empieza por guion bajo:

Terminal
# estructura de un bloque
blocks/
└── data-table/
    ├── _data-table.json   # definición + modelo + filtros
    ├── data-table.css
    └── data-table.js

Tipos de campo

Estos son los tipos que más vas a usar y cómo se renderizan en el markup del bloque:

ComponenteUsoMarkup resultante
textTextos cortos: títulos, etiquetasTexto plano
richtextPárrafos con formato y enlaces<p>, <ul>…
referenceImágenes del DAM<picture>
aem-contentEnlaces a páginas<a>
aem-content-fragmentSelector de Content FragmentRuta del fragmento
booleanInterruptores y block optionsClase CSS si usa classes_*

Variantes y block options

Los campos llamados classes o classes_* no se renderizan como filas: se convierten en clases del bloque. Así un mismo bloque soporta variantes sin duplicar código.

_data-table.json
{
  "component": "boolean",
  "valueType": "boolean",
  "name": "classes_caption",
  "label": "Show Caption",
  "value": false
}
index.html
<!-- con el interruptor activado -->
<div class="data-table caption">
  <div><div>/content/dam/…/tabla</div></div>
</div>
data-table.js
const showCaption = block.classList.contains('caption');

Content Fragments con GraphQL

Cuando el contenido es tabular o se reutiliza en varias páginas, guárdalo en un Content Fragment y léelo desde el bloque con una persisted query.

  1. Crea el modelo en Tools → Content Fragment Models y habilítalo.
  2. Crea el endpoint en Tools → GraphQL y publícalo.
  3. Guarda la query en el GraphQL Query Editor y publícala.
  4. Configura CORS en publish para los orígenes de aem.page y aem.live.
!
Codificación de la rutaAEM no decodifica %2F en las variables de una persisted query. Mantén las barras de la ruta sin codificar.

Buenas prácticas

  • Etiquetas y descripciones en el mismo idioma en todos los modelos.
  • Marca como required solo lo que de verdad rompe el bloque.
  • Prefiere select o boolean a campos de texto libre para variantes.
